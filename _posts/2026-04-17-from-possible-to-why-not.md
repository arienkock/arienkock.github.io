This is a placeholder draft for a bigger idea: when something becomes easier to do, it eventually crosses a threshold where it goes from merely possible to "why not?"

The more important shift is not just frequency. Entirely new practices become thinkable.

## Core argument

At high effort, a capability is reserved for exceptional cases.

At low effort, the same capability becomes default behavior.

At very low effort, new workflows appear that were previously inconceivable.

## Example 1: on-demand software environments

If you can create isolated software environments on demand, but it is expensive and manual, you only use it for major testing efforts.

But once environment creation is fast and cheap, it becomes reasonable to ask:

- why not spin one up for every significant test run?
- why not include isolated capacity tests in the normal CI pipeline?

The capability is the same. The effort profile is different. That changes engineering behavior.

## Example 2: conversational analysis of Jira data

I could always analyze Jira data, but the setup and reporting effort used to be prohibitive.

Now I can generate custom reports quickly and have an interactive conversation with the data.

That means the bottleneck moves:

- from data extraction to question quality
- from report generation to decision quality
